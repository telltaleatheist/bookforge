## The cue-count rule (measured, not assumed)

e2a emits **exactly one VTT cue per rendered chunk it assembled** - including
a chunk whose cue text is EMPTY. `vtt_cue_text` (e2a `lib/conf_models.py:116`)
strips every SML marker, so a row that is nothing but a marker (a bare
`[break]`) becomes an empty payload and e2a still writes its cue. So:

    len(parse_vtt(reference.vtt)) == len(sentences.json)

Do NOT compare the cue count against a `<book>.m4b.vtt` sidecar from a
BookForge project: that sidecar is not e2a output. It is ffmpeg re-muxing the
m4b's embedded `mov_text` track back to WebVTT
(`electron/sidecar-migration.ts` -> `extractVttFromM4b`), which drops every
empty cue and prints `MM:SS.mmm` instead of e2a's `HH:MM:SS.mmm`.
